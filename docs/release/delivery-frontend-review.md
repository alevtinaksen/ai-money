## DFE-01 — P1: подтверждение старого импорта после смены счёта/файла

- frontend/src/components/BankImport.tsx:118,137 меняют только account/file, сохраняя batch и confirming. :71–75 подтверждают batch.id. :5–11 интерфейс Batch не включает account_id; review показывает лишь номер пакета и количество строк.
- backend app/services/bank_import.py:23–35 возвращает account_id; import_row передаёт именно batch.account_id, а не текущий select пользователя.
- Сценарий: preview файла на счёте A → выбрать B → подтвердить оставшийся preview. Экран показывает выбранный B, сервер записывает на A. Аналогично можно выбрать другой файл, но подтвердить строки старого.
- Исправление: инвалидировать batch/confirming при любой смене файла или счёта; включить account_id в Batch и явно показывать неизменяемый счёт пакета при review/confirm; не оставлять старый confirm после неуспешного нового upload.
- Тест: previewA→selectB/file2→кнопка confirm старого пакета отсутствует; новое preview показывает правильный account_id.

## DFE-02 — P2: истёкшая локальная сессия не восстанавливается через UI

- frontend/src/api.ts:29–34 теряет HTTP status и возвращает обычный Error с приглашением войти локально. App.tsx:63–65 только показывает сообщение; :108 Login доступен только !signedIn; signedIn нигде не сбрасывается.
- bot/app/api/deps.py:36 токен действует3600с и живёт только в памяти процесса.
- Сценарий: оставить страницу на час либо перезапустить локальный backend; любой запрос401. «Повторить загрузку» использует тот же просроченный токен; обещанного действия локального входа на экране нет. Hard reload помогает, но уничтожает черновики в памяти.
- Исправление: typed ApiError.status и явная кнопка re-auth/обработчик401; для Telegram инструкция переоткрытия, для localhost возможность получить новый токен. Сохранить pending draft/idempotency при обновлении авторизации.
- Тест: успешный вход→401→повторный локальный вход→успешная загрузка без ручной перезагрузки страницы.

## DFE-03 — P2: история валюты архивного счёта недоступна

- frontend/src/components/Dashboard.tsx:58 валюты формируются только из RUB+accounts; App.tsx:49 загружает /accounts без include_archived. Backend finance_analytics.py сохраняет архивные счета в balances_by_currency и истории.
- Сценарий: единственный USD счёт имеет историю → архивировать → после нового входа selector содержит толькоRUB, хотя balances содержитUSD и операции на сервере сохранены. До USD-истории нельзя добраться.
- Исправление: валюты из union active accounts, summary.balances_by_currency, summary.totals_by_currency и текущего выбора; при необходимости отдельный список справочных валют исторических данных.
- Тест: archive soleUSD→reload→USD остаётся доступна→история показывается.

## DFE-04 — P1: старые суммы подписываются новой валютой

- Dashboard.tsx:53–55 немедленно меняют currency; :66–83 продолжают показывать старый summary.period_income/expense, форматируя новой currency. App.tsx:47–64 обновляет summary только после всего Promise.all; при сетевой ошибке старое значение остаётся без ограничения.
- Сценарий: RUB доход1000 → переключитьUSD → до ответа видно1000USD; если сеть оборвалась, это значение остаётся на карточке вместе с ошибкой. Это не конвертация, а неверная подпись финансовой суммы.
- Исправление: использовать серверную summary.currency (она уже есть в backend DashboardSummary, отсутствует в TS Summary) для snapshot либо скрывать/помечать несовпадающий snapshot до ответа; предпочтительно читать totals_by_currency[currency], не подписывать чужой агрегат. Аналогичный контракт snapshot для периода.
- Тест: RUB1000,USD20; отложенный/ошибочныйUSD fetch никогда не показывает1000USD.
