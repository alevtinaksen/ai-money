# Эксплуатация и будущий сервер

Mac используется для разработки. Рабочий бот и Mini App развёрнуты на Render, данные хранятся в Supabase PostgreSQL. Контейнер остаётся дополнительным переносимым способом запуска.

## Контейнер

Dockerfile собирает React и Python API, запускает приложение непривилегированным пользователем.
В образ не копируются .env, базы, личные настройки IDE, зависимости с компьютера.
Настройки передаются при запуске. /health/live показывает жизнь процесса, /health/ready реально обращается к БД.

При настроенном bot/.env:

    docker compose build api
    docker compose up -d --force-recreate api
    docker compose logs --tail=50 api

Сервис слушает только127.0.0.1:8000 на хосте, внутри контейнера локальный вход отключён.
В этом режиме в обычном браузере без Telegram вы увидите экран входа; это ожидаемо.
Хранилище finance-data — именованный том. Не выполнять down -v: это удалит данные.
Для Telegram после настройки HTTPS WEBAPP_URL и собственного токена:

    docker compose --profile telegram up -d bot
    docker compose logs --tail=50 bot

Один процесс polling на токен. HTTP API не запускает polling сам.
До обновления: backup и проверка восстановления, quality и preflight. После обновления: readiness, логи, реальная запись/редактирование и сверка остатков. Для отката сохранять прежний образ и совместимую резервную копию; новые записи после backup нельзя молча потерять.

## Что требуется перед публичной эксплуатацией

Проверенный HTTPS reverse proxy, постоянное хранилище, закрытый локальный вход, собственные секреты runtime, договорённость о резервных копиях и восстановлении.
Для PostgreSQL указать DATABASE_URL и проверить dump/restore; SQLite backup.py не подходит. Драйвер всегда проверяет TLS-сертификат и имя сервера. Для отдельного доверенного CA передайте путь к PEM-файлу в DATABASE_SSL_CA_FILE. sslmode=require/verify-full принимаются с полной проверкой; остальные режимы отклоняются.
Нужны общий лимитер для нескольких API workers, наблюдение за единственным poller, retention черновиков/выписок, политика персональных данных и процесс обновлений.
Не использовать исходный Render free template с локальной SQLite: он сохранён в docs/legacy только для истории.
Сон/выключение Mac не является отказоустойчивым сервером; никакой внутренний self-ping это не исправит.

ISO 27001 — стандарт системы управления, а не результат одного теста программы. Эта поставка не является сертификацией.


## Существующий Render Python service

render.yaml описывает native Python service ai-money-bot, совпадающий по имени с существующим сервисом. Не создавать второй сервис при обновлении. Native runtimes Render включают npm: build устанавливает bot/requirements.txt и выполняет npm ci/build в frontend. Start запускает один uvicorn worker из bot; React dist обслуживается тем же сервером, VITE_API_URL при сборке не требуется. Dockerfile остаётся отдельным вариантом запуска.

Перед переключением проверить ветку, build/start, /health/ready и env. APP_ENV=production, HOST=0.0.0.0, ALLOW_LOCAL_LOGIN=false; TELEGRAM_MODE=webhook требует HTTPS SERVER_URL и секрет. WEBAPP_URL должен совпадать с опубликованным Mini App. AI включается после согласия владельца. Пользователь вводит секреты напрямую в Render; не хранить их в репозитории или логах.

DATABASE_SCHEMA выбирает заранее созданную отдельную PostgreSQL-схему (например ai_money_v2) без изменения public. Приложение квалифицирует таблицы, внешние ключи и schema_version; одной смены search_path недостаточно. Подготовить схему из текущих ORM-моделей, закрыть USAGE/табличные права anon/authenticated/PUBLIC и включить RLS без FORCE, если backend подключается владельцем. Проверить пустые таблицы, version=2 и сохранность старой схемы до запуска. Это намеренный новый бюджет, не миграция.

Документация Render: [native runtimes](https://render.com/docs/native-runtimes), прочитана 9 октября 2026. Успешная сборка отдельно от живой приёмки Telegram и Gemini. Free service может засыпать: первое обращение может задерживаться, это не круглосуточный SLA.

## Проверка независимости от ноутбука — 9 октября 2026

Облачный адрес: https://ai-money-bot-0y05.onrender.com. SERVER_URL и WEBAPP_URL в Render указывают на него; TELEGRAM_MODE=webhook. Telegram передаёт сообщения непосредственно облачному API. Mini App обращается к API на своём домене, без локального прокси или туннеля на Mac.

После остановки обоих локальных тестовых серверов /health/ready вернул ready. Владелец с телефона отправил /start и открыл «Бюджет»: бот ответил, счета были видны. Это подтверждает работу без локальных серверов. Физический сон/выключение Mac и сохранение новой операции в таком состоянии отдельно не проверялись.

Выбран бесплатный сервер Render. По [официальным условиям](https://render.com/docs/free), прочитанным 9 октября 2026, Free засыпает после 15 минут без входящего трафика; следующее обращение пробуждает его примерно за минуту. Данные бюджета находятся в Supabase, а не на временном диске Render. Владелец решил пока оставить Free. Минимальный платный compute в Dashboard указан как $7/месяц; тариф не меняли. Переход убирает засыпание Free, но не гарантирует скорость внешнего AI и не заменяет проверки восстановления базы.
