# Веб-интерфейс и Telegram Mini App

Реализовано: React 18 + TypeScript, сервер FastAPI — источник счетов, категорий, операций и итогов. Локальных запасных финансовых записей нет.

## Контракт и сценарии

- Telegram отправляет подписанный initData; loopback-вход требует разрешения backend. Bearer хранится только в памяти вкладки.
- VITE_API_URL пуст по умолчанию: /api на том же origin. Vite слушает loopback, proxy направлен в 127.0.0.1:8000; VITE_DEV_API_TARGET меняет только dev target.
- Ручная операция: форма → pending → серверное подтверждение или видимая ошибка с сохранённой формой. POST использует client_id, PUT/DELETE — revision. Общий close guard действует для кнопки, Escape и Dialog.
- Строгий денежный ввод, переводы между разными счетами одной валюты. Балансы и месячные итоги приходят с сервера; период UTC.
- Валюты показаны отдельно. История загружается по 50 операций; поиск/фильтры применяются к загруженным страницам, это подписано.
- Счета: создание с начальным остатком, редактирование метаданных, архивирование. Остаток существующего счёта напрямую не меняется.
- Категории: серверный CRUD и parent_id. Названия истории не подменяются локальными догадками.
- Текст, аудиофайл и фото → редактируемые предложения → отдельное явное подтверждение каждой строки. Неизвестный получатель перевода требует выбора.
- Pending и неопределённый результат создания (сеть/timeout/HTTP408/5xx) удерживают точный payload и client_id в памяти открытой формы. Редактирование, закрытие и замена AI-результата/файла блокируются; доступен повтор того же запроса, backend возвращает существующую запись без повторного списания. HTTP4xx кроме408 до первого неопределённого результата позволяет исправить/закрыть черновик. Более поздний4xx не доказывает отсутствие первой записи и не снимает блокировку. Успешный ответ снимает её; отдельной offline-очереди и фоновых повторов нет.
- Подтверждение создания требует HTTP200 с непустым id, целой revision≥1, конечной положительной числовой amount и совпадением суммы/account_id/type с отправленным запросом. Неполный или другой JSON (включая null/{}) остаётся неопределённым результатом, даже если HTTP-код успешен.
- При HTTP401 в открытом черновике локальный loopback-профиль предлагает вход внутри той же формы. Новый Bearer заменяет истёкший; payload/client_id и неопределённый статус сохраняются, следующий retry пользователь запускает отдельно. Неуспешный повторный вход не закрывает форму. Telegram требует свежего initData при новом запуске: текущая форма предупреждает о сверке истории перед повторным вводом после перезапуска.
- Транспорт очищает локальный Bearer после401 только если он совпадает с Authorization исходного запроса. Запоздалый ответ старой сессии и401 для Telegram initData не удаляют более новую локальную сессию.
- Комментарий редактора инициализируется сырым note и сохраняется без визуального форматтера. Краткая подпись в списке не изменяет данные операции.
- Старый локальный кэш не участвует в книге. Есть отдельный экспорт и явная очистка только старых ключей.
- Модальные формы удерживают фокус и скрывают фон от клавиатуры. Zoom разрешён.

## Модули и проверки

App.tsx координирует экраны; hooks/useLedger.ts — серверные снимки и записи; hooks/useCreationAttempt.ts — удержание незавершённого POST и его точного повтора; api/client.ts — транспорт; api/session.ts — сессия/старый кэш; utils/money.ts — ввод; components/ai — review; components/shared/Dialog.tsx — фокус.

Команды: npm ci, npm test, npm run build из frontend. Vitest проверяет транспорт, ошибки, auth, revisions, страницы, серверные остатки, поздние ответы, AI review/retry и фокус. Регрессии creationRetry.test.tsx моделируют commit → потерю ответа → close/Escape/reparse → retry для полного App; один client_id и одно списание. Hook tests различают definitive4xx и неопределённый commit; editor tests сохраняют сырой note при правке суммы. Общий gate: python3 scripts/project.py quality.

Tailwind 4 использует современный CSS; целевые браузеры: Safari16.4+, Chrome111+, Firefox128+. Старые Telegram WebView требуют отдельной проверки совместимости.

## Навигация локального дизайн-стенда

Bridge действует только в iframe по пути /frontend/dist/index.html на loopback-hostname; обычное приложение его не слушает. Parent отправляет same-origin postMessage с type="ai-money:preview:navigate", requestId (непустая строка до100 символов), route. App проверяет source===window.parent и точный origin; другие источники игнорирует. Whitelist: dashboard, transactions, accounts, analytics, add-expense, categories, currencies, settings, ai-review, backup. Analytics/currencies ведут на существующую главную; categories/backup — в настройки с явной подсказкой; add-expense и ai-review открывают существующие формы.

Ответ parent: type="ai-money:preview:navigation-result", исходные requestId/route, status="applied"|"blocked"|"unsupported", message. Busy/неопределённое создание, любая открытая форма, загрузка или отсутствие входа отклоняют переход. Для расхода нужен активный счёт. Bridge меняет только экран/видимость форм; не сохраняет, не экспортирует и не сбрасывает данные автоматически. Hash-маршруты не являются контрактом обычного приложения.

## Ограничения и запланировано

CSV preview/confirm реализованы в backend, UI импорта пока отсутствует. Прямой записи микрофона нет — выбор аудиофайла. Черновик и client_id теряются при перезагрузке/закрытии вкладки: после неопределённой записи сначала проверьте историю, прежде чем вводить её заново. Фоновой offline-очереди нет. Конфликт версии требует закрыть редактор, обновить данные и открыть свежую операцию. Окончательная дизайнерская приёмка, физический Telegram, PostgreSQL concurrency и реальный облачный provider отдельно не приняты.
