# Веб-интерфейс и Telegram Mini App

Статус: реализовано в отдельной сборке передачи Алине. Это единый интерфейс React с сервером FastAPI; браузер не хранит собственную финансовую книгу.

## Контракт

- Telegram передаёт подписанный initData в `Authorization: tma ...`; локальный вход доступен отдельной кнопкой только на loopback-хосте и с разрешения сервера. Токен хранится в памяти вкладки.
- `VITE_API_URL` по умолчанию пуст: `/api` на том же origin. Vite направляет `/api` в `127.0.0.1:8000`; dev server слушает loopback.
- Данные счетов, категорий и истории всегда приходят с сервера. Ошибка сети показывается пользователю; фиктивных успешных операций и запасной истории нет.
- Сумма в форме проверяется как десятичная строка, затем отправляется строкой с двумя знаками. Вычисление балансов делает сервер.
- Черновик → проверка → явное подтверждение. POST сохраняет стабильный client_id при повторе неизменённого черновика. PUT/DELETE отправляют revision; конфликт требует обновить историю.
- Перевод разрешён между разными счетами одной валюты. FX не имитируется курсом 1:1.
- Остатки представлены отдельно по валютам. Доход и расход за месяц получены из серверной агрегации; история загружается страницами по 25 операций.
- Счета и категории можно создать, переименовать и архивировать; история остаётся. При создании счёта задаётся начальный остаток (в том числе отрицательный долг); он не создаёт доход. Для выписки выбирают остаток перед её началом. При редактировании счёта баланс напрямую не меняется.
- AI из текста, аудиофайла и фото лишь предлагает поля. Несколько операций в одном ответе требуют ручной разбивки; ничего не сохраняется автоматически.
- CSV: загрузка → предварительный просмотр → включение/исключение строк → комментарий/категория → подтверждение. Поддерживается только документированный общий формат, не произвольная выписка любого банка.

## Структура

`frontend/src/App.tsx` координирует загрузку и разделы; `components/Dashboard.tsx` показывает итоги; `TransactionForm.tsx` управляет черновиком; `AiDraft.tsx` распознаванием; `Directories.tsx` счетами/категориями; `BankImport.tsx` пакетами и `ImportRow.tsx` отдельной строкой; `api.ts` транспортом; `money.ts` точной валидацией ввода.

## Проверки

`cd frontend && npm ci && npm test && npm run build`.
Регрессии в `src/money.test.ts`, `src/api.test.ts`, `src/components/TransactionForm.test.tsx`: отрицательные/нечисловые/слишком точные суммы, отсутствие автосохранения, одинаковый ключ повторной отправки, явная ошибка API и заголовок авторизации.
Проверка реального браузера и API документируется отдельно в отчёте передачи. Тесты с подменённым fetch не являются подтверждением реального Telegram или Mac.

## Ограничения

После перезагрузки вкладки несохранённый ручной черновик теряется. Импорт хранится на сервере, но UI пока не содержит список прежних пакетов. Для голоса используется выбор аудиофайла; запись микрофона в браузере не реализована. Конфликт версии редактирования разрешается повторным открытием свежей операции, автоматического слияния правок нет. Изменение формы баланса сервером надёжно; UI не предлагает универсальную кнопку undo для всех действий.


## Исправления после пользовательской проверки

При HTTP 401 интерфейс очищает истёкшую сессию и возвращает к входу без перезагрузки; Telegram требует открыть мини-приложение заново. При изменении счёта или файла прежний предпросмотр импорта сбрасывается. Исторические валюты сохраняются в выборе после архивации счетов. До окончания новой загрузки месячные суммы подписаны валютой того серверного ответа, к которому они относятся, поэтому сумма RUB не переименовывается в USD. Регрессии добавлены в App.test.tsx, BankImport.test.tsx и Dashboard.test.tsx.
