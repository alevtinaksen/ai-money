# AI-предложения и Telegram-черновики

Реализовано: services/ai_parser.py возвращает AIParsedResult; конечные суммы проходят строгую проверку. Значения<=0, NaN/Infinity, более двух десятичных знаков и суммы выше лимита отклоняются.
REST /api/ai/parse-text, /parse-voice, /parse-receipt не пишут операции.
Для облачного текста и аудио суммы предложений сверяются с числами исходной записи через Decimal. «5000 рублей»/«пять тысяч рублей» требуют ровно5000; ответы50/0/55 дают уточнение, без черновика и финансовой записи. Поддержаны десятичные рубли, явные рубли+копейки и масштабы «2 тысячи». Несколько предложений допустимы при нескольких явных суммах с единицами рублей; арифметика цены/количества, даты, номера карт и неоднозначные числовые записи требуют уточнения. Несовпадение не исправляется скрытым округлением или умножением. В сообщении уточнения выводятся первые300символов распознанного текста, чтобы человек видел основание суммы.
«Полтора»/«полторы» нормализуется как1.5 перед масштабом: полтора миллиона→1500000, полторы тысячи→1500, полтора рубля→1.50. Необработанные дроби вроде «четверть миллиона» требуют уточнения; нельзя принять оставшееся слово «миллион» как1000000. Несколько явных сумм со знаком₽ проходят ту же сверку.
Необработанные масштабы/модификаторы (миллиард, триллион, сотни, десятки, пара) также требуют уточнения, а не принятия оставшегося числа1/2/5. В контексте карты/счёта распознаются идентификаторы с№ и масками****; они не становятся суммой покупки.
Groq сверяется с отдельным ответом transcription. Gemini audio должен вернуть transcript рядом с transactions; отсутствие transcript вызывает уточнение. Это проверка согласованности ответа модели, а не независимое доказательство того, что она правильно услышала речь. Фото чеков сохраняет прежний сценарий и не проходит текстовый amount guard; ручное подтверждение по-прежнему обязательно.
Тело HTTP ограничено до5МБ+64КБ служебного multipart до разбора, отдельный файл до5МБ. Принимаются ограниченные MIME-типы. Каждый внешний вызов, включая Groq transcription, занимает один общий слот: максимум4 одновременных вызова на процесс/event loop, ожидание слота до2секунд, полный запрос до45секунд. Groq text также имеет HTTP timeout20секунд. Groq audio pipeline освобождает слот transcription перед генерацией предложений; вложенного захвата нет. Отмена и timeout освобождают слот. Процессный лимит10распознаваний в минуту на пользователя. Для нескольких серверных процессов нужен общий лимитер; сейчас серверный rollout не выполнен.

services/bot_drafts.py сохраняет черновик с владельцем, исходным message ID, статусом и сроком30минут. Полный список предложений выводится до кнопки подтверждения, при необходимости несколькими сообщениями. Подтверждение меняет статус условным SQL и пишет весь пакет в одной транзакции. Ошибка любой операции откатывает пакет. Повторное подтверждение уже подтверждённого черновика ничего не добавляет.
Суммы и остатки в Telegram форматируются непосредственно из Decimal, без промежуточного float: «5 000,00 RUB» и «250,50 RUB». Сумма сообщения соответствует сохранённому payload черновика.

Telegram safe_flow обслуживает только личные чаты. Редактирование/удаление уже созданных операций — через веб-интерфейс. Неопределённый счёт/категория требуют уточнения; переводы требуют двух счетов одной валюты.
Аудио принимается как voice OGG/Opus, Telegram audio (MP3/M4A/WAV/WebM/OGG) или document с поддерживаемым аудио MIME. Для application/octet-stream/отсутствующего MIME известное расширение определяет формат, затем контейнер сверяется с байтами. Это проверка заголовка, а не полное декодирование: повреждённый кодек может отклонить поставщик. Gemini получает M4A как audio/m4a. Документы других типов отклоняются с понятным ответом. Фактическая загрузка ограничена5МБ во время записи в память; весь download/getFile до35секунд, streaming timeout30секунд. Пустота, несовпадение формата, ошибки скачивания/облака не создают финансовых операций.
Bot polling отдельный от HTTP API. Процессные словари прежнего редактирования и локальный OCR удалены из runtime.
Логи ошибок Telegram сохраняют только класс исключения, без текста ошибки/traceback/SQL-параметров: финансовые суммы, заметки и ключи не попадают в журнал при сбое подготовки черновика.

Проверки: bot/tests/test_ai_preview.py, test_ai_provider.py, test_bot_audio.py, test_bot_drafts.py, test_http.py. Регрессии проверяют реальный Router→mock HTTP adapter→SQLite draft→confirm, все поддержанные Telegram варианты, одно списание при повторном confirm и неизменный баланс при ошибках. Шесть параллельных transcription и смешанные Groq/Gemini запросы имеют peak4; очередь, отмена и полный timeout покрыты отдельно. Синтетические заголовки в wire-тестах не доказывают облачное распознавание речи.
Wrong-amount регрессия воспроизводит корректный transcription5000 при ошибочных LLM50/0/55; проверки не допускают черновик/операцию. Положительные wire-сценарии сверяют spoken5000 и250.50 с payload и русским отображением. Отдельно проверены числа словами, тысячи, копейки, цена/количество, даты, цифры карты, отсутствие выдуманной суммы и сохранение нескольких предложений фото-чека. Исходный конкретный сбой действующего бота не воспроизведён: пользователь помнит величины приблизительно.
Реальные облачные распознавания и доставка Telegram требуют ключей владельца; поставка не выдаёт синтетические тесты за такую проверку.
Пока нет автоматической очистки старых подтверждённых черновиков; retention/экспорт/удаление персональных данных — отдельная задача до публичного многопользовательского запуска.

Диагностика Gemini: только завершённый кандидат finishReason=STOP допускается к проверке предложений. MAX_TOKENS отклоняется даже при синтаксически правильном JSON, чтобы не сохранить часть пакета. HTTP-ошибки/timeout/transport, envelope, candidate, content и proposal различаются статическими кодами в журнале gemini_failure; выводятся только HTTP status и разрешённые finish/block enum. Текст исключений, тела ответов, заголовки, URL, transcript и свободные provider messages не логируются. Дополнительные регрессии: test_gemini_response.py и Router→Gemini→draft в test_bot_audio.py. Живой тест 5000 дал правильный черновик; причина отказа второго теста250.50 пока не установлена, требуется повтор после диагностического обновления.
