# AI-предложения и Telegram-черновики

Реализовано: services/ai_parser.py возвращает AIParsedResult; конечные суммы проходят строгую проверку. Значения<=0, NaN/Infinity, более двух десятичных знаков и суммы выше лимита отклоняются.
REST /api/ai/parse-text, /parse-voice, /parse-receipt не пишут операции.
Для облачного текста и аудио суммы предложений сверяются с числами исходной записи через Decimal. «5000 рублей»/«пять тысяч рублей» требуют ровно5000; ответы50/0/55 дают уточнение, без черновика и финансовой записи. Поддержаны десятичные рубли, явные рубли+копейки и масштабы «2 тысячи». Несколько предложений допустимы при нескольких явных суммах с единицами рублей; арифметика цены/количества, даты, номера карт и неоднозначные числовые записи требуют уточнения. Несовпадение не исправляется скрытым округлением или умножением. В сообщении уточнения выводятся первые300символов распознанного текста, чтобы человек видел основание суммы.
«Полтора»/«полторы» нормализуется как1.5 перед масштабом: полтора миллиона→1500000, полторы тысячи→1500, полтора рубля→1.50. Необработанные дроби вроде «четверть миллиона» требуют уточнения; нельзя принять оставшееся слово «миллион» как1000000. Несколько явных сумм со знаком₽ проходят ту же сверку.
Необработанные масштабы/модификаторы (миллиард, триллион, сотни, десятки, пара) также требуют уточнения, а не принятия оставшегося числа1/2/5. В контексте карты/счёта распознаются идентификаторы с№ и масками****; они не становятся суммой покупки.
Groq сверяется с отдельным ответом transcription. Gemini audio должен вернуть transcript рядом с transactions; отсутствие transcript вызывает уточнение. Это проверка согласованности ответа модели, а не независимое доказательство того, что она правильно услышала речь. Фото чеков сохраняет прежний сценарий и не проходит текстовый amount guard; ручное подтверждение по-прежнему обязательно.
Тело HTTP ограничено до5МБ+64КБ служебного multipart до разбора, отдельный файл до5МБ. Принимаются ограниченные MIME-типы. Каждый внешний вызов, включая Groq transcription, занимает один общий слот: максимум4 одновременных вызова на процесс/event loop, ожидание слота до2секунд, полный запрос до45секунд. Groq text также имеет HTTP timeout20секунд. Groq audio pipeline освобождает слот transcription перед генерацией предложений; вложенного захвата нет. Отмена и timeout освобождают слот. Процессный лимит10распознаваний в минуту на пользователя. Для нескольких серверных процессов нужен общий лимитер; сейчас серверный rollout не выполнен.

services/bot_drafts.py сохраняет черновик с владельцем, исходным message ID, статусом и сроком30минут. Полный список предложений выводится до кнопки подтверждения, при необходимости несколькими сообщениями. Подтверждение меняет статус условным SQL и пишет весь пакет в одной транзакции. Ошибка любой операции откатывает пакет. Повторное подтверждение уже подтверждённого черновика ничего не добавляет.
Суммы и остатки в Telegram форматируются непосредственно из Decimal, без промежуточного float: «5 000,00 RUB» и «250,50 RUB». Сумма сообщения соответствует сохранённому payload черновика.

Telegram safe_flow обслуживает только личные чаты. Редактирование/удаление уже созданных операций — через веб-интерфейс. Неопределённый счёт/категория требуют уточнения; переводы требуют двух счетов одной валюты.
Аудио принимается как voice OGG/Opus, Telegram audio (MP3/M4A/WAV/WebM/OGG) или document с поддерживаемым аудио MIME. Для application/octet-stream/отсутствующего MIME известное расширение определяет формат, затем контейнер сверяется с байтами. Это проверка заголовка, а не полное декодирование: повреждённый кодек может отклонить поставщик. Gemini получает M4A как audio/m4a. Документы других типов отклоняются с понятным ответом. Фактическая загрузка ограничена5МБ во время записи в память; весь download/getFile до35секунд, streaming timeout30секунд. Пустота, несовпадение формата, ошибки скачивания/облака не создают финансовых операций.
Bot polling отдельный от HTTP API. Процессные словари прежнего редактирования и локальный OCR удалены из runtime.
Логи ошибок Telegram сохраняют только класс исключения, без текста ошибки/traceback/SQL-параметров: финансовые суммы, заметки и ключи не попадают в журнал при сбое подготовки черновика.

Проверки: bot/tests/test_ai_preview.py, test_ai_provider.py, test_bot_audio.py, test_bot_drafts.py, test_http.py. Регрессии проверяют реальный Router→mock HTTP adapter→SQLite draft→confirm, все поддержанные Telegram варианты, одно списание при повторном confirm и неизменный баланс при ошибках. Шесть параллельных transcription и смешанные Groq/Gemini запросы имеют peak4; очередь, отмена и полный timeout покрыты отдельно. Синтетические заголовки в wire-тестах не доказывают облачное распознавание речи.
Wrong-amount регрессия воспроизводит корректный transcription5000 при ошибочных LLM50/0/55; проверки не допускают черновик/операцию. Положительные wire-сценарии сверяют spoken5000 и250.50 с payload и русским отображением. Отдельно проверены числа словами, тысячи, копейки, цена/количество, даты, цифры карты, отсутствие выдуманной суммы и сохранение нескольких предложений фото-чека. Исходный конкретный сбой действующего бота не воспроизведён: пользователь помнит величины приблизительно.
Реальные облачные распознавания и доставка Telegram требуют ключей владельца; поставка не выдаёт синтетические тесты за такую проверку.
Пока нет автоматической очистки старых подтверждённых черновиков; retention/экспорт/удаление персональных данных — отдельная задача до публичного многопользовательского запуска.

Диагностика Gemini: только завершённый кандидат finishReason=STOP допускается к проверке предложений. MAX_TOKENS отклоняется даже при синтаксически правильном JSON, чтобы не сохранить часть пакета. HTTP-ошибки/timeout/transport, envelope, candidate, content и proposal различаются статическими кодами в журнале gemini_failure; выводятся только HTTP status и разрешённые finish/block enum. Текст исключений, тела ответов, заголовки, URL, transcript и свободные provider messages не логируются. Дополнительные регрессии: test_gemini_response.py и Router→Gemini→draft в test_bot_audio.py. Живые тесты5000 и250.50 дали правильные черновики; первый отказ250.50 при повторе не воспроизвёлся, исходная причина не установлена.

Скорость: для проверенной модели gemini-3.8-flash используется thinkingConfig.thinkingLevel=LOW; GEMINI_THINKING_LEVEL=default возвращает поведение поставщика. Другие модели не получают неподтверждённую настройку. Все проверки суммы/transcript и отказ незавершённого ответа сохраняются. Это настройка для уменьшения задержки, а не гарантия мгновенного ответа.
Одна операция и кнопки подтверждения отправляются одним Telegram сообщением; пакет нескольких операций по-прежнему показывает все строки перед отдельным подтверждением. Создание черновика выбирает основной счёт из уже прочитанного списка и не повторяет чтение accounts. Инварианты владельца, точность и атомарное сохранение не меняются.
Логи ai_money_timing выводят только разрешённый stage, целое число ms и completed. Этапы: gemini, bot_download, bot_preview, draft_create, draft_confirm, bot_confirmation. Провайдер/preview и callback totals пересекаются — их нельзя складывать. completed для preview/callback означает завершение обработчика, а не доказательство сохранения; draft_confirm не включает Telegram-доставку. Текст входа/ответа, идентификаторы пользователя, ключи и exception repr не записываются. Используется существующий uvicorn.error, без включения INFO для HTTP-клиентов.

По последнему живому голосовому тесту09октября Gemini3.8 timeout45секунд; preview обработал ошибку за46.46секунд, скачивание666ms. Этот тест НЕ принят как успешное распознавание. Для следующей приёмки default изменён на stable gemini-3.5-flash-lite (официально audio/image/text input и structured output, default minimal thinking). Его настройка LOW не отправляется; все amount/transcript/STOP guards сохранены. Saved GEMINI_MODEL в Render нужно менять отдельно. Быстроту/качество доказывает только следующий живой замер, не смена модели и не wire tests.
REST нормализует MIME codec parameters (audio/webm;codecs=opus→audio/webm), сохраняя whitelist и limit5МБ.

Этот замер относится к прежнему multimodal пути; основная задержка приходится на Gemini, а не запуск локального процесса.

Реализован переключаемый GEMINI_AUDIO_MODE=transcribe (default multimodal). Один общий путь для API/бота: validate_audio+consent → Gemini3.5Transcribe с inlineData/VERBATIM/ru-RU → проверенный текст → существующий GEMINI_MODEL JSON → validate_source_amounts → предложения. Транскрипция не получает список счетов/категорий и финансовые инструкции; контекст передаётся только текстовой стадии. Ошибка не создаёт финансовую запись, не переключается скрыто на старый audio path и не вызывает вторую стадию при отказе STT.

### Ответ транскрипции: REST segment text и word annotations

Транскрипция принимает plain `content.parts[].text`, основной REST
`content.parts[].audioTranscription.text` и word-only пример из руководства
`audioTranscription.words[].word`. Официальная REST схема AudioTranscription
определяет `text` как обязательный текст сегмента, `words` — необязательные данные
при word_timestamp. При наличии segment text читается только он, включая пунктуацию;
words не добавляются повторно. Пустой/повреждённый text не заменяется words.
Сегменты соединяются в исходном порядке с пробелом, без исправления сумм/единиц.
Speaker/time metadata не превращается в пользовательский текст. STOP обязателен,
thought-поля исключаются, итог до10000символов. Смесь отдельного непустого plain text
с audioTranscription отклоняется, чтобы не терять или дублировать речь.
Финансовый JSON по-прежнему читается только из plain text и проходит amount guard;
поставщик/модель/ключи и ручное подтверждение сохраняются.

Основание: живой запрос15:13MSK дал missing_text/STOP. Выпуск8161659 добавил
word-only поддержку, но повторный запрос15:37MSK дал invalid_transcript/STOP:
download370ms, STT1741ms completedFalse, preview3208ms. Первая правка была неполной.
Реальный payload не логируется/не читался; основной текст подтверждён официальной
схемой, а воспроизводимый regression без optional words выдавал тот же код отказа.
См. [Parsing transcription output](https://ai.google.dev/gemini-api/docs/generate-content/transcribe)
и [REST discovery schema v1beta](https://generativelanguage.googleapis.com/$discovery/rest?version=v1beta)
(`AudioTranscription.properties.text/words`).

Регрессии test_transcript_contract.py проверяют оба REST формата на пути
Router→STT→JSON→pendingdraft5000/250.50, отказ ошибочной50, основной текст с optional
words без дублирования, порядок, повреждённый text без fallback, общий лимит,
мысли/пустые/повреждённые/незавершённые/mixed ответы и приватность диагностики.
Живое устранение отказа и ускорение требуют повторной приёмки после публикации.

## Границы из аудита — 9 октября 2026

Офлайн-текст теперь проходит тот же `validate_source_amounts` по оригиналу,
что облачные предложения: неподдержанные масштабы, дроби и номера карт не становятся
частичной суммой. Узкое уточнение не создаёт финансовой записи. HTTP медиа использует
общий audio_mime: MP3/M4A/WAV/OGG aliases и известное расширение при generic MIME;
неизвестный формат остаётся 415, контейнер/consent/provider/size проверки сохраняются.
Groq transcription и generation разделяют общий deadline CLOUD_REQUEST_SECONDS (45 с),
включая ожидание слотов; каждый внешний запрос занимает один слот, внешнего слота
на всю цепочку нет. Отмена освобождает слот. Это ограничивает максимальное ожидание,
но не доказывает ускорение Gemini или отсутствие cold start Free Render.
Проверки: test_audit_input_boundaries, test_http, существующие provider/preview suites.
