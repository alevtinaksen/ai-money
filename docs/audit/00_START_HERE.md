# Итог глубокого аудита AI Money

Дата: 26 сентября 2026. Объект: предоставленный `ai-money-clean.zip`, 67 исходных файлов. Аудит без изменения проекта, без обращения к реальному боту/удалённому API и базе Алины. Доказательства: статическое чтение критичных путей, существующие тесты, изолированные Python/TypeScript сценарии, сборка frontend, dependency audit, официальные источники.

**Вердикт: не готов к доверенному финансовому учёту и многопользовательскому доступу.** Основные проблемы — обход авторизации, недостоверные суммы, рассогласование журнала и остатков, ложное подтверждение сохранения. Нужна последовательная починка финансового контракта; полная смена технологического стека сейчас не обоснована.

## С чего начать

1. Прочитать этот файл и [план A0–A9](02_ACTION_PLAN.md).
2. Для каждой задачи открыть точные доказательства в [реестре находок](01_FINDINGS.md).
3. Для отказов/параметров использовать [ISO/RFC assessment](03_RESILIENCE_ISO_RFC.md), для внешних оснований — [исследование](04_RESEARCH.md).
4. После исправлений передать Алине [инструкции Mac/Gemini](05_ALINA_MAC_GEMINI.md) и фактический handoff выполненной работы.
5. Для повторения проверок — [порядок воспроизведения](06_VERIFICATION.md) и папка evidence.

## Что реально воспроизведено

| Проверка | Наблюдение | Что это означает |
|---|---|---|
| Авторизация, DEBUG=False | Без credentials/с неверной подписью HTTP200; query/header выбирают user ID | Публичный API нельзя считать защищённым |
| Права объекта | Пользователь1 через PUT изменил синтетический баланс пользователя2 со100 до90 | Одной починки входа недостаточно, нужны ownership checks |
| Два пересекающихся списания | Журнал10+20, остаток100→80 вместо70 | Реальная потеря изменения в модели учёта |
| Отрицательная сумма | Expense−5 даёт100→105 | Схема и сервис принимают неверный денежный ввод |
| Перевод | PUT без получателя списывает; RUB→USD зачисляется1:1 | Нет единых проверок типа операции и валют |
| Onboarding/seed | Второй пользователь IntegrityError; удалённая демозапись возвращается после GET | Деморежим смешан с пользовательскими данными |
| Backend parser | 250,50→50;1 500→1;26/09 500→26009 | Обычные форматы сумм распознаются неверно |
| Backend arithmetic+parser | 0.1+0.2→30000000000000004 в parsed draft | Сочетание float и regex разрушает сумму; запись этой величины в БД не проверялась |
| Frontend voice | «5 тысяч»→5; «сто рублей пятьдесят копеек»→150 | Нужны единый parser contract и подтверждение черновика |
| Ошибки сети | POST401 возвращает локальную транзакцию; DELETE offline=true | UI способен выдать неуспех за сохранение |
| Слияние данных | Сервер800 перекрывается local900; server edit20 остаётся local10 | Бот и Mini App не сходятся к единой истории |
| Пустое состояние | Пустой серверный список превращается в14 демонстрационных счетов | Новый пользователь видит придуманные финансы |
| Пользовательские категории |35 сохранённых категорий заменяются16 встроенными | Порог количества вызывает потерю настроек |
| Месячный dashboard API | month_offset0 и−12 одинаковы, recent_count20 | «Месячная» сводка не отражает полный период |

Дополнительно статически подтверждены: выбор любого фото в UI создаёт фиксированный расход850 (FE-03); удаление перевода в UI неверно обращает знак источника (FE-02); настройка API в `.env.example` не соответствует коду и оставляет внешний default (OPS-04); отказ primary DB включает локальную fallback DB (RES-01). Эти сценарии не выдаются за выполненную браузерную или production проверку.

## Что прошло и чего это не доказывает

- **7 existing pytest PASS**, Python3.11.9. Тесты не покрывают перечисленные негативные сценарии; некоторые закрепляют demo/upsert. Python3.12 и Mac не проверены.
- **TypeScript + Vite build PASS** в отдельной копии. Это проверка сборки, не пользовательский UAT.
- **npm audit: 0 известных уязвимостей** в проверенном lock-наборе.
- **pip-audit: 0 известных уязвимостей** среди50 разрешённых зависимостей незакреплённого requirements на дату запуска. Это другой набор версий, чем окружение pytest, и не установленное окружение Алины.
- Surface harness выполнен; исходный отчёт сохранён, но **его общий балл не используется**. Он ошибочно объявляет package.json битым, хотя реальная сборка проходит; отсутствие Git в ZIP ничего не доказывает о репозитории Алины; frontend lock существует. Автоматические size/lint signals полезны как указатели, не итоговый вердикт.

## Рекомендуемое решение

Сначала закрыть A0–A6: локальный безопасный стенд, права, Money+транзакции, чистая модель, достоверная синхронизация, аналитика и подтверждаемый AI-ввод. Затем выполнить модульный рефакторинг и Mac-приёмку. React/FastAPI/aiogram можно сохранить. Новизна библиотек не исправляет ошибку, при которой удалить перевод означает ещё раз списать деньги.

Документы созданы отдельно, исправления не вносились. Ни одна находка не помечена закрытой. Пакет не отправлен Алине автоматически; он подготовлен для вашей проверки и последующей передачи.
